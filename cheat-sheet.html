AGGREGATE / GROUP BY / HAVING

SELECT c.title,
       COUNT(*) AS rows_n,
       COUNT(e.score) AS score_n,
       AVG(e.score) AS avg_score
FROM Course c
LEFT JOIN Enroll e ON e.cid = c.cid
GROUP BY c.cid, c.title
HAVING COUNT(e.score) >= 1
ORDER BY avg_score DESC;

  • COUNT(*) นับทุกแถว; COUNT(col) ข้าม NULL
  • SUM/AVG/MIN/MAX ข้าม NULL; ถ้าไม่มี non-NULL มักคืน NULL
  • คอลัมน์ใน SELECT ที่ไม่ aggregate ต้องอยู่ใน GROUP BY
  • WHERE กรองแถวก่อนกลุ่ม; HAVING กรองกลุ่มหลัง aggregate

DDL + CONSTRAINTS

CREATE TABLE Enroll (
  sid INT,
  cid CHAR(2),
  score DECIMAL(5,2) CHECK(score BETWEEN 0 AND 100),
  PRIMARY KEY (sid,cid),
  FOREIGN KEY (sid) REFERENCES Student(sid),
  FOREIGN KEY (cid) REFERENCES Course(cid)
);

ER MODELING — อ่านกฎธุรกิจ

Entity
สิ่งที่มีตัวตนและต้องเก็บข้อมูลแยก เช่น Student, Course
Attribute
คุณสมบัติของ entity/relationship; derived คำนวณได้; multivalued มีหลายค่า
Relationship
ความสัมพันธ์ระหว่าง entity เช่น Student enrolls Course
Cardinality
จำนวนสูงสุด: 1:1, 1:N, M:N
Participation
จำนวนต่ำสุด: total = ต้องเข้าร่วมอย่างน้อย 1; partial = อาจเป็น 0
Weak entity
ไม่มี key สมบูรณ์เอง; ใช้ owner key + partial key ผ่าน identifying relationship

อ่านคำในโจทย์

ประโยคตีความ
แต่ละ A มี B ได้หลายตัวA → B = N
แต่ละ B เป็นของ A เดียวB → A = 1
A ทุกตัวต้องมี BA total participation (min 1)
A อาจไม่มี BA partial participation (min 0)

EXAM FAULT CHECK — ตรวจคำตอบก่อนส่ง

  1. เขียนคอลัมน์ที่โจทย์ต้องการก่อน แล้วหา table ที่ให้คอลัมน์นั้น
  2. JOIN ทุกคู่มี ON หรือยัง? จำนวนแถวพองเพราะ Cartesian product หรือไม่?
  3. โจทย์ขอ “ทุก A แม้ไม่มี B” ต้องรักษาฝั่ง A ด้วย LEFT JOIN
  4. NULL ใช้ IS NULL; อย่าใช้ = NULL; ระวัง NOT IN + NULL
  5. กรองแถวใช้ WHERE; กรอง COUNT/AVG ของกลุ่มใช้ HAVING
  6. SELECT non-aggregate อยู่ใน GROUP BY ครบหรือไม่?
  7. Composite PK/FK จำนวนและลำดับ columns ตรงกันหรือไม่?
  8. Cardinality ถามจำนวนสูงสุด; participation ถามจำนวนต่ำสุด
