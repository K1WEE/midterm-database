1. SELECT, WHERE, CASE & COALESCE

เลือกคอลัมน์, เงื่อนไข, CASE จำแนกกลุ่ม และ COALESCE

SELECT s.name, e.score,
       CASE WHEN e.score >= 80 THEN 'Pass (High)'
            WHEN e.score >= 70 THEN 'Pass'
            ELSE 'Retake' END AS status,
       COALESCE(s.dept, 'Undeclared') AS department
FROM Student s
JOIN Enroll e ON e.sid = s.sid
WHERE e.score BETWEEN 70 AND 100
ORDER BY e.score DESC, s.name ASC;

4. AGGREGATE / GROUP BY / HAVING

SELECT c.title,
       COUNT(*) AS all_rows,
       COUNT(e.score) AS scored_n,
       AVG(e.score) AS avg_score
FROM Course c
LEFT JOIN Enroll e ON e.cid = c.cid
GROUP BY c.cid, c.title
HAVING COUNT(e.score) >= 1
ORDER BY avg_score DESC;
ผลลัพธ์: NULL ถูกข้ามโดย COUNT(col) และ AVG

Database2278.50
  • COUNT(*) นับทุกแถว; COUNT(col) ข้ามแถวที่คอลัมน์เป็น NULL
  • SUM/AVG/MIN/MAX ข้าม NULL; ถ้ากลุ่มว่าง/NULL ล้วน → AVG/SUM ได้ NULL
  • กฎเหล็ก: คอลัมน์ใน SELECT ที่ไม่อยู่ใน Aggregate ต้องอยู่ใน GROUP BY
  • WHERE กรองแถวก่อน Grouping; HAVING กรองสรุปผลหลัง Grouping

5. SUBQUERY, CTE & MODIFICATIONS

Subquery ใน WHERE และ Correlated Subquery

-- IN: อยู่ในชุดคำตอบ
SELECT name FROM Student WHERE sid IN (
  SELECT sid FROM Enroll WHERE score >= 80
);
-- Correlated Subquery: อ้างอิงแถวด้านนอก (outer table)
SELECT s.name FROM Student s WHERE EXISTS (
  SELECT 1 FROM Enroll e WHERE e.sid = s.sid AND e.score > 75
);

x > ANY(S) มากกว่าอย่างน้อย 1 ค่า · x > ALL(S) มากกว่าทุกค่า · CTE: WITH t AS (SELECT ...) SELECT ...

กับดัก: NOT IN เจอ NULL ใน Subquery จะคืนค่าว่าง ให้ใช้ NOT EXISTS ปลอดภัยกว่า

Database Modification ด้วย Subquery

INSERT INTO high_scores SELECT sid, cid, score FROM Enroll WHERE score >= 85;
DELETE FROM Enroll WHERE cid IN (SELECT cid FROM Course WHERE fee > 2800);
UPDATE Student SET dept = 'ENG' WHERE sid IN (SELECT sid FROM Enroll WHERE cid='C1');

6. DDL, VIEWS, INDEX & AUTHORIZATION

-- Table & Constraints
CREATE TABLE Enroll (
  sid INT, cid CHAR(2), score DECIMAL(5,2) CHECK(score BETWEEN 0 AND 100),
  PRIMARY KEY (sid, cid),
  FOREIGN KEY (sid) REFERENCES Student(sid) ON DELETE CASCADE,
  FOREIGN KEY (cid) REFERENCES Course(cid)
);
-- Views: CREATE VIEW name AS ... (Updatable: 1 ตาราง, ห้ามมี aggregate/distinct/group by)
CREATE VIEW cs_students AS SELECT sid, name FROM Student WHERE dept='CS';
DROP VIEW IF EXISTS cs_students;
-- Index: B-Tree ค้นหา O(log N) แทน Full Scan O(N) (สร้างบน WHERE, JOIN, ORDER BY)
CREATE INDEX idx_stu_dept ON Student(dept);
-- Authorization: สิทธิ์และการส่งต่อ
GRANT SELECT, INSERT ON Course TO student_role;
GRANT UPDATE(score) ON Enroll TO instructor_role WITH GRANT OPTION;
REVOKE INSERT ON Course FROM student_role;
ฝึกใช้โดยปิดผลลัพธ์ก่อน แล้วคำนวณจำนวนแถวและค่า NULL ด้วยมือ · สูตรโครงสร้าง SQL: SELECT ... FROM ... JOIN ... ON ... WHERE ... GROUP BY ... HAVING ... ORDER BY

1. DBMS FUNDAMENTALS (25%)

Database
กลุ่มข้อมูลขนาดใหญ่ที่สัมพันธ์กันและบูรณาการเพื่อแทนส่วนหนึ่งของโลกจริง
DBMS
ซอฟต์แวร์นิยาม เก็บ ค้นคืน คุมความถูกต้อง (Integrity), ความปลอดภัย (Security), Concurrency และ Crash Recovery
Schema / Instance
Schema = แบบแปลนโครงสร้าง (คงที่) · Instance = ข้อมูลจริง ณ เวลาหนึ่ง
3 Abstractions
Physical: เก็บอย่างไร (blocks/index) · Logical: เก็บอะไร (tables/attrs) · View: ผู้ใช้เห็นส่วนใด
Data Independence
เปลี่ยน Physical Schema โดยไม่ต้องแก้ Logical Schema หรือโปรแกรม
Engine Parts
Storage Manager (จัดการบล็อกข้อมูล), Query Processor (Parse → Optimize → Eval), Transaction Manager (คุม ACID)

ทำไมไม่ใช้ File System: ลด Redundancy & Inconsistency, มีมาตรฐานสิทธิ์กลาง, รองรับ Concurrent Access ไม่ให้ข้อมูลทับกัน, กู้คืนได้เมื่อระบบดับ (Atomicity)

2. RELATIONAL MODEL & KEYS

ชนิด Keyนิยามและข้อแตกต่างตัวอย่างใน Student
Superkeyชุด Attribute ที่ระบุ Tuple ได้ไม่ซ้ำ (อาจมีคอลัมน์เกิน){sid}, {email}, {sid, name}
Candidate KeyMinimal Superkey: เอาตัวใดออกแล้วจะไม่ Unique ทันที{sid}, {email}, {national_id}
Primary KeyCandidate key ที่เลือกใช้ระบุแถวหลัก (คงที่, ไม่เป็น NULL){sid}
Foreign KeyAttribute ในตารางลูกที่อ้าง PK/Candidate key ตารางแม่Enroll.sid → Student.sid

การเลือก PK ในทางปฏิบัติ: เลือก Surrogate Key เช่น student_id เพราะสั้น คงที่ ระบบคุมเอง ทำ Index เร็ว · ไม่เลือก email (เปลี่ยนได้) หรือ national_id (PII ข้อมูลอ่อนไหว ยาว 13 หลัก)

4. ER MODELING — แปลงกฎธุรกิจ (15%)

Entity / Set
สิ่งที่มีตัวตนและแยกจากสิ่งอื่นได้ เช่น Student, Course (สี่เหลี่ยมผืนผ้า)
Attributes
Simple/Composite: ค่าเดี่ยว vs แตกกิ่ง (Address → street, city)
Single/Multi-valued: ค่าเดียว vs วงรีคู่ (phones)
Stored/Derived: เก็บจริง vs วงรีประ (age คำนวณจาก birth_date)
Key/Partial: ขีดเส้นใต้ทึบ (PK) vs ขีดเส้นใต้ประ (Discriminator)
Relationship
ความสัมพันธ์ระหว่าง Entity (สี่เหลี่ยมข้าวหลามตัด / Diamond)
Cardinality
1:1, 1:N, M:N — อ่านสองทิศทาง (แต่ละ A มี B ได้กี่ตัว, แต่ละ B มี A ได้กี่ตัว)
Participation
Total (เส้นคู่ / บังคับ): ทุกตัวต้องมีคู่ · Partial (เส้นเดี่ยว / ทางเลือก): อาจไม่มีคู่
Weak Entity
สี่เหลี่ยมคู่ + ข้าวหลามตัดคู่: ไม่มี PK เอง ต้องใช้ Owner PK + Partial Key

5. กฎแปลง ER DIAGRAM เป็น RELATIONAL SCHEMA

องค์ประกอบ ERกฎการแปลงเป็น Tableตัวอย่าง Relational Schema
Entity ปกติสร้างตารางตามปกติ, simple attribute เป็น columnStudent(sid PK, name, major)
Composite Attrแตกเป็นคอลัมน์ย่อยในตารางเดิมCustomer(cid PK, name, street, city, zip)
Multi-valued Attrสร้างตารางใหม่: Owner PK (FK) + ค่านั้นCust_Phones(cid FK, phone_no, PK(cid, phone_no))
1:N Relationshipนำ PK ฝั่ง 1 ไปใส่เป็น FK ในฝั่ง NDept(did PK) · Emp(eid PK, did FK)
1:1 Relationshipใส่ FK ฝั่งใดฝั่งหนึ่ง (เลือกฝั่ง Total) + ใส่ UNIQUEPerson(pid PK) · Passport(pass_no PK, pid FK UNIQUE)
M:N Relationshipสร้าง Junction Table: FK ทั้ง 2 ฝั่งเป็น Composite PKEnroll(sid FK, cid FK, grade, PK(sid, cid))
Recursive (Self)ใส่ FK ชี้กลับมาที่ PK เดิมEmp(eid PK, name, mgr_id FK REFERENCES Emp(eid))
Weak Entityตาราง weak มี Owner PK (FK) + Partial key เป็น PKDependent(eid FK, dep_name, PK(eid, dep_name))

6. CASE STUDY: BAD VS GOOD DESIGN & FAULT CHECK

4 ข้อผิดพลาดในการออกแบบที่ต้องแก้ให้ได้:

  • Repeating Groups: ตารางมี prod1, prod2, prod3 → แตกเป็น Orders(order_id PK) + Order_Items(order_id FK, prod_id FK, qty, price)
  • Text Blob: เก็บประวัติใน text ยาวๆ → แตกเป็น structured tables เช่น Diagnoses, Prescriptions
  • Missing Index: ค้นหา 500M แถวช้ามาก → CREATE INDEX idx ON posts(user_id, created_at DESC);
  • ACID Crash: โอนเงินแล้วเซิร์ฟเวอร์ดับ → ใช้ START TRANSACTION; ... COMMIT; + CHECK (balance >= 0)

Checklist ก่อนส่งกระดาษคำตอบ:
1. JOIN ทุกคู่มี ON ชัดเจน · 2. ไม่ใช้ = NULL · 3. ทุกคอลัมน์ใน SELECT ที่ไม่อยู่ใน Aggregate ต้องอยู่ใน GROUP BY · 4. M:N ต้องมี Junction Table · 5. 1:1 FK ต้องใส่ UNIQUE · 6. สูตรตอบสั้น: นิยาม 1 ประโยค → เหตุผล 1 ประโยค → ตัวอย่าง

เขียนลงกระดาษจริงด้วยลายมือขนาดกะทัดรัด · เน้นเขียน Pattern โครงสร้าง SQL และกฎแปลง ER ไว้เป็นแม่แบบ · ขอให้โชคดีกับการสอบ!
